# 目黑静香牙科诊所 (目黒しずか歯科クリニック) 官方网站

这是一个参考了 ar-dc.com 架构，用于正式开业后的诊所官网（静态 HTML 项目）。
项目内置了一个轻量级的静态网站生成器，通过修改 **`src/` (源码)** 来自动生成最终用于上线的 **`dist/` (发布文件)**。

## 核心原则（只需记住这一条！）

> **只允许编辑 `src/` 目录里的内容。`dist/` 是全自动生成的“成品”，不需要手动去修改它。**

无论是网页文案、CSS 样式还是图片素材，全部都在 `src/` 里面进行管理和编辑。执行构建命令后，`dist/` 文件夹会被整个重新生成。
如果您直接修改了 `dist/*.html` 里面的代码，下一次构建时所有的修改都会被无情覆盖（这样设计是为了避免双重维护的混乱）。

## 目录结构

```text
02.静-new/
├── src/                      ← ★ 您只需要编辑这里（源码文件）
│   ├── data.js               … 诊所信息、诊疗内容、价格表、新闻公告等数据
│   ├── layout.js             … 公共布局（网页 <head> / 顶部导航 / 底部 / 通用横幅）
│   ├── components.js         … 公共组件（如出诊时间表、项目网格等）
│   ├── content/index.js      … 首页的具体内容
│   ├── build.js              … 核心构建脚本
│   ├── watch.js              … 文件监听脚本（修改后自动重新构建）
│   └── assets/               … 静态资源（← CSS 和 图片 都在这里）
│       ├── css/style.css
│       ├── js/main.js
│       └── images/…
│
├── dist/                     ← ★ 自动生成的目录（手不要动！）＝ 用于直接上线的网页
│   ├── *.html, medical/*.html
│   ├── assets/               … 直接从 src/assets 复制过来的静态资源
│   └── sitemap.xml, robots.txt
│
├── reference/                … 开发参考资料（不需要上传服务器）
├── package.json / README.md
```

## 本地开发指南

| 操作目的 | 执行命令 |
|---|---|
| 执行单次构建 | `npm run build` |
| **实时监听并自动构建**（推荐） | `npm run watch` |
| 启动本地预览服务器（需新开终端） | `npm run serve` → 访问 http://localhost:8000 |

💡 **推荐的工作流**：
在您的开发工具中打开两个终端窗口。
一个窗口运行 `npm run watch`（只要您按下保存键，`dist/` 里的网页就会自动更新）。
另一个窗口运行 `npm run serve`（开启本地服务器）。
接下来，您只需要在 `src/` 里修改代码并保存，然后去浏览器里刷新页面就能看到最新效果了。

### 我该去哪里修改内容？

| 我想修改的内容 | 去哪个文件里改？ |
|---|---|
| 网页文案、价格表、新闻公告、诊所基础信息 | `src/data.js` |
| 顶部导航栏 / 底部版权区 / 通用的预约横幅 | `src/layout.js` |
| 首页特有的结构和文案 | `src/content/index.js` |
| 内页（如医生介绍、各项治疗等）的结构和文案 | `src/build.js` |
| 网页颜色、字体、CSS 样式 | `src/assets/css/style.css`（可通过修改 `:root` 里的变量一键换色）|
| 图片素材 | 放到 `src/assets/images/` 目录下 |

## 部署到服务器 (VPS / Ubuntu + Nginx)

由于该项目生成的是纯静态网页，部署过程非常简单。您只需要把最新生成的 `dist/` 里面的内容上传到服务器即可。以下是标准的部署流程：

### 1. 确保本地拥有最新版本
在本地电脑的终端中运行一次构建命令，生成最新的静态文件：
```bash
npm run build
```
执行完毕后，所有用于上线的文件都在本地的 `dist/` 文件夹中。

### 2. 将文件上传到服务器
使用 FTP 客户端（如 FileZilla、WinSCP）或命令行，将本地 `dist/` 文件夹里的 **所有内容** 上传并覆盖到 Ubuntu 服务器的网站根目录（例如 `/var/www/shizuka-dental`）。

*(注意：是上传 `dist` 里面的文件，不要把整个 `dist` 文件夹当成一个大壳子丢进去，否则网页路径会变成 `/dist/index.html` 导致 403 错误)*

**使用命令行 (SCP) 上传的示例：**
```powershell
scp -r D:\编程\003.网页建站\02.静-new\dist\* root@您的服务器IP:/var/www/shizuka-dental/
```

### 3. 设置服务器文件权限 (解决 403 错误)
为了防止 Nginx 出现 `403 Forbidden` 没有访问权限的错误，请登录您的服务器，将网页目录的所有权转交给 Nginx 的运行用户（Ubuntu 默认为 `www-data`）：
```bash
sudo chown -R www-data:www-data /var/www/shizuka-dental
sudo chmod -R 755 /var/www/shizuka-dental
```

### 4. 刷新 CDN 缓存（非常关键）
如果您的域名接入了 Cloudflare 等 CDN 服务，上传完毕后必须登录 CDN 后台，执行 **Purge Everything (清除所有缓存)**，否则用户和浏览器依然会看到旧版的网页！

## 待办与注意事项

- 部分**诊所环境、设备照片**目前使用的是占位图或是低画质图片，待实拍图确认后需在 `src/assets/images/` 中进行替换。
- `contact.html` 表单目前为**纯前端展示**。如果需要实现真实的邮件发送功能，需要在服务器端配置相应的 PHP 接口或其他后端服务。
- `src/data.js` 中的**费用和公告信息**均为测试样本，请在正式上线前更新为真实的诊所数据。
- 上传巨型照片前，请务必先进行压缩（网页图片应尽量控制在 500KB 以下），以确保极佳的移动端加载体验。
